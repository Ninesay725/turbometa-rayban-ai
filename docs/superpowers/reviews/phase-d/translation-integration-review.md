## P1 — Recheck the camera lease when reading and sending an image

Location: [LiveTranslateScreen.kt:216](D:/Coding/Workspaces/Android/turbometa-rayban-ai/android/app/src/main/java/com/smartview/glassai/ui/screens/LiveTranslateScreen.kt:216), with [LiveTranslateViewModel.kt:207](D:/Coding/Workspaces/Android/turbometa-rayban-ai/android/app/src/main/java/com/smartview/glassai/viewmodels/LiveTranslateViewModel.kt:207).

`ScreenTranslationVisual.nextJpeg()` reads global `wearables.streamState/currentFrame`; it never verifies that its `owner` still owns that stream. The parent helper explicitly permits a newer `startStream(otherOwner, …)` to replace ownership. An old translation image loop can remain alive while that happens: the replacement synchronously goes through Stopped into Waiting, which the polling loop simply skips, then the loop reads the replacement owner's frames when Streaming returns. `isCurrent(current)` only checks the translation attempt, not the camera lease. Its later `stopStream(oldOwner)` correctly preserves the new owner, but that stop fence does not prevent uploading the new owner's image.

Correction: obtain a frame through an owner/generation-checked parent accessor, and recheck that same lease after background encoding before returning/sending JPEG. On lease loss, stop only this visual operation and retain the existing camera-unavailable guidance. Coordinate the small accessor with the parent; do not use another unscoped snapshot provider.

Regression: start visual owner A, replace the shared stream with B without first stopping A's image loop, publish B's frame, and advance the loop. A must send no B frame, report loss of its visual input, and its cleanup must leave B running. Also replace the lease while A's encoding is suspended.

## P2 — Observe SCO loss after initial preparation

Location: [LiveTranslateViewModel.kt:314](D:/Coding/Workspaces/Android/turbometa-rayban-ai/android/app/src/main/java/com/smartview/glassai/viewmodels/LiveTranslateViewModel.kt:314), [LiveTranslateViewModel.kt:137](D:/Coding/Workspaces/Android/turbometa-rayban-ai/android/app/src/main/java/com/smartview/glassai/viewmodels/LiveTranslateViewModel.kt:137).

The route waits for `isBluetoothScoConnected.first { it }` once, returns true, and exposes no subsequent route state to the attempt. Disconnecting the headset after preparation (during configuration or recording) therefore leaves `input=GLASSES` and the translation running. `BluetoothAudioManager` publishes disconnection/phone fallback, but nothing in this ViewModel consumes it. The service cannot detect that routing changed because its `PcmAudioSource` contract only supplies bytes; it can continue recording/rerouting or become silent while the UI still claims glasses input.

Correction: keep an attempt-owned route-loss observer through configuration/recording. The smallest safe response is to stop with visible microphone guidance and require explicit retry; an automatic phone fallback would instead need a source restart and accurate route state. Cancel/fence the observer before normal cleanup so the disconnect caused by Stop cannot fail a successor.

Regression: route connects, then disconnects before ACK and after READY. Both must retire the old source/service/image work and clear the glasses-input claim; a late disconnect from the retired route must not stop the replacement attempt.

## P2 — The SCO ownership check becomes stale while awaiting availability

Location: [LiveTranslateViewModel.kt:311](D:/Coding/Workspaces/Android/turbometa-rayban-ai/android/app/src/main/java/com/smartview/glassai/viewmodels/LiveTranslateViewModel.kt:311), [BluetoothAudioManager.kt:76](D:/Coding/Workspaces/Android/turbometa-rayban-ai/android/app/src/main/java/com/smartview/glassai/managers/BluetoothAudioManager.kt:76).

The wrapper checks MODE_NORMAL/SCO before `isBluetoothAvailable.first { it }`, which can suspend for three seconds. A call or another feature can acquire communication audio during that wait. On resumption, the wrapper neither repeats the check nor verifies ownership of the connected broadcast before calling `startBluetoothSco()`/accepting readiness. The underlying manager marks every CONNECTED broadcast as its own `isBluetoothScoOn`; cleanup then calls `stopBluetoothSco()` even when this instance never requested that other connection. Thus the comment promising not to take over another route is not maintained across the wait.

Correction: recheck communication-route availability immediately before requesting SCO, and distinguish a route this attempt requested from a foreign broadcast when deciding readiness and cleanup. A foreign route must not be stopped by this attempt. This needs the Bluetooth boundary/parent's coordination; merely checking the UI attempt identity does not establish global audio ownership.

Regression: while translation waits for headset availability, acquire a foreign communication route and deliver CONNECTED. Translation must not claim the route or stop it on timeout/Stop. Also cover cancellation before this attempt ever requested SCO.

## P2 — Snapshot service text before closing when saving stopped history

Location: [LiveTranslateViewModel.kt:234](D:/Coding/Workspaces/Android/turbometa-rayban-ai/android/app/src/main/java/com/smartview/glassai/viewmodels/LiveTranslateViewModel.kt:234), with [LiveTranslateService.kt:309](D:/Coding/Workspaces/Android/turbometa-rayban-ai/android/app/src/main/java/com/smartview/glassai/services/LiveTranslateService.kt:309).

`finish()` cancels the text collector and closes the service, then saves `ui.value.text`. That UI value is an asynchronously collected copy of `connection.text.value`. If the service publishes its newest transcript and Stop/error wins before the UI collector runs, history saves the older snapshot or omits the entry entirely. Closing the actual service clears its text, so reading the authoritative flow afterward cannot recover it. The existing history test drains the collector before each Stop and misses this ordering.

Correction: take a bounded snapshot of the current attempt's `connection.text.value` before cancelling/closing; use it for the stopped display/history, then keep the existing attempt fence and 50-entry RAM cap. Do not read a retired connection or rely on collector scheduling to save the final snapshot.

Regression: publish a newer service text value and call Stop before advancing the UI collector; history and stopped display must contain that newest value exactly once. Repeat with immediate service ERROR and with a late old-attempt text publication after restart.
