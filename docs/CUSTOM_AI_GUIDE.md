# 自定义 AI 使用说明

## 接入模型

首页进入“自定义 AI”，在设置中填写兼容 OpenAI **Chat Completions** 的 API 地址、模型名与密钥。可以填 API 基础路径（例如 `https://你的服务/v1`），也可以填完整的 `/chat/completions` 地址。密钥只在 App 本地加密保存，清空并保存即删除；不需要把密钥发到聊天中。

不同厂商的专有 Responses、Messages、Realtime 协议不能直接当成 Chat Completions 地址。可使用厂商的兼容入口，或自行部署转换服务。模型能否看图、调用工具取决于服务/模型能力；不支持时关闭对应开关，文字问答和翻译仍可使用。自部署 Ollama 等服务需手机能够访问，手机里的 localhost 指手机自身，不是开发电脑。

默认只允许 HTTPS。自行部署的局域网 HTTP 服务必须明确打开 HTTP 开关；此时请求与凭据不加密。应用不跟随重定向发送密钥。设置模型不会自动联网，只有发送消息/摘要时才发出请求。

## 对话、拍照和操作

- 输入中文问题或翻译要求；系统听写用于把语音转为可编辑文字，然后由用户发送。听写服务由 Android 提供，可能使用网络，是否可用取决于手机；它与自定义大模型 API 是两条独立路径。
- 对支持图片的模型，可选择“拍照并提问”，通过现有 DAT 共享会话取得画面，并请求必要的相机权限。
- 开启工具能力后，模型可按请求拍照、显示自己的文字/状态/音乐卡片、翻页，以及播放/暂停/切歌。没有系统菜单、任意命令、发消息或安装应用工具。
- 回答可显示在镜片和朗读。朗读复用现有云端 TTS/系统 TTS；不是要求每个自定义聊天模型都提供音频 API。手机与眼镜的实际音频路由需要真机验证。
- 取消/清空/离开页面会停止请求和朗读；照片、对话、摘要不保存到数据库或日志。镜片是否显示成功必须在 Display 真机验收，模拟器不能替代。

## 通知摘要

先授予 Android 通知访问，再单独开启“允许 AI 读取通知”并选择应用包名。授权与微信镜片预览开关独立。只收集启用后新收到的、应用实际公开的通知，不读取聊天数据库或恢复历史消息。

使用助手中的“总结通知”入口，可选所有允许的应用或某个应用。此请求将选定资料交给当前配置的模型服务；普通聊天不会自动取得通知。摘要请求不提供音乐、拍照等操作工具，因此通知中的文字不能通过这条请求触发设备动作。

缓存仅在内存保留最近 20 条；移除通知、收回访问、关闭开关、缩小允许列表、服务断开或锁屏会清理相关数据。被系统隐藏的内容不会被补全。摘要不作为后续普通聊天的上下文发送。

## 音乐

默认支持网易云音乐、汽水音乐和 QQ 音乐的 Android 媒体会话；QQ 音乐包名为 `com.tencent.qqmusic`。用户自定义允许列表会保留，必要时手动加入 QQ 音乐。

先在手机音乐 App 播放一首歌并开启音乐桥接。能执行哪些动作以应用发布的媒体会话为准；这不包含在服务内搜索任意歌曲、登录账号或绕过会员要求。指定不可用的应用时，不会悄悄控制另一个音乐 App。

## OpenClaw

自定义 AI 直接调用模型 API，不依赖 OpenClaw。已有 OpenClaw 用户仍可使用独立入口。客户端协议兼容与 OpenClaw 服务器升级是两件事；服务器实际版本、配对和策略需要在自己的网关核实。

本次兼容核对、测试证据和仍需验证的范围见 [OpenClaw 报告](superpowers/reviews/custom-ai/openclaw-compatibility.md)；选择与网关匹配的兼容方式后重新连接，认证失败不会自动降低协议/权限。

本次对照官方已发布的 `v2026.9.4`（2026-09-11 发布）适配协议 4，聊天走官方节点事件接口，不额外申请控制端权限。设置提供“当前网关（协议 4）”“官方协议 3–4”和“旧版自定义网关（协议 3）”；后者保留原项目的自定义协议行为，不能保证任意旧官方网关兼容。旧网关先确认服务器版本，按实际情况选择；认证被拒绝时不会自动降级。

配对后缓存的节点凭据绑定到具体网关和设备身份。需要重新配对时，可在设置清除该网关的本地配对凭据，再连接并在网关批准设备。相机命令还受网关自己的允许列表约束；聊天已连接并不等于服务器允许拍照。当前节点接口一次只发送一个对话请求，等待回答期间不会重复发送。

每次重新订阅或重连会启用新的服务器聊天会话，避免超时前的旧回复被当成新请求结果。手机当前聊天列表仍可见，但重连后服务器不会自动继承这份列表。配对批准使用 `openclaw devices list` 中的请求 ID（`openclaw devices approve <requestId>`），批准后在 App 再次点击连接。

- [Meta Wearables FAQ](https://developers.meta.com/wearables/faq/)：相机、音频、显示和自选云/本地处理能力，配对仍通过 Meta AI。
